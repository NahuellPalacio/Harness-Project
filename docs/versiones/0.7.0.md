# v0.7.0 — Los dos harness conviven de verdad

> 11-08-2026 · commit `be616e0` · 151 tests en verde

El README prometía desde 0.1.0 que un proyecto podía tener `analisis` y `desarrollo` a la vez.
El código lo sostenía **solo si los nombrabas juntos en el mismo comando** — y el camino real es
el otro: un repo de relevamiento que recibe su primer código meses después.

## Qué se hizo

- **Instalar es aditivo**: se lee el lockfile y se conserva lo que el proyecto ya tenía
- **El orden pasa a ser canónico**, no de instalación
- **Conservar se anuncia**: `se conserva lo ya instalado: analisis`
- 21 tests más en `tests/casos/06-composicion.ps1`, que cubren el ciclo incremental completo

## Qué se decidió, y por qué

**Conservar en silencio sorprende tanto como borrar en silencio.** Por eso el instalador dice
qué conservó. Para quedarse con un conjunto exacto el camino sigue siendo `-Uninstall` y
reinstalar — no se agregó un flag para "reemplazar", porque es una operación destructiva que
merece dos pasos.

**El orden de los harness es canónico y no de instalación.** Llegar al mismo conjunto instalando
los dos juntos o agregando uno después producía archivos distintos, y el `-Update` siguiente
generaba un diff que no correspondía a ningún cambio real.

## Lo que se rompió en el camino

🔴 **Agregar un segundo harness borraba el primero.** Instalar reemplazaba el bloque del
`CLAUDE.md` y el lockfile con el conjunto nuevo, y los archivos del primero **quedaban en disco
fuera del inventario**: invisibles para `-Doctor` y para `-Uninstall`. Fallaba en silencio y
ningún `-Update` posterior los recuperaba.

🔴 **`-Harness analisis,desarrollo` andaba por una vía y no por la otra.** En sesión interactiva
el parser de PowerShell arma el array; invocado con `-File` —desde un `.cmd`, desde CI, desde
otro script— el mismo texto llegaba como una cadena literal y abortaba con *"no existe el
harness 'analisis,desarrollo'"*. **Es la forma que documenta el README, así que nunca se probó
por la vía que fallaba.**

## Lo que quedó abierto

- Nadie compone dos harness todavía en un proyecto real. El disparador previsto es el IGE
  recibiendo su primer código

## Dónde seguir

La composición quedó cubierta por tests pero **sin uso real**. La primera vez que se usó de
verdad fue mucho después, y funcionó.

Para verificarla:

```powershell
.\install.ps1 -Project <ruta> -Harness analisis -Usuario "<nombre>"
.\install.ps1 -Project <ruta> -Harness desarrollo -Usuario "<nombre>"
```

El segundo comando tiene que decir `se conserva lo ya instalado: analisis`.
